How Archive works

Three ways in, one place for your data, and the same rules for everyone.

  • The web app for you and your team.
  • The HTTP API for your code, with a token.
  • MCP for your AI assistant.
  • All three pass the same permissions before they touch a record or a file.
More detail

Archive is one Go program on top of Postgres. Your tables live in Postgres. File contents live on disk or in S3-compatible storage.

The permissions are Postgres itself. People, spaces and tokens are real database roles, and every table has row-level security, so each query only sees rows from your spaces.

Archive never calls an AI model on its own. Your assistant does the thinking and sends Archive code to run.

Quick start

One line starts Archive on your machine with Docker.

curl -fsSL https://raw.githubusercontent.com/Mulholland-Inc/archive/main/install.sh | ARCHIVE_ADMIN_EMAIL=you@example.com sh

Use your own email: you become the first owner. Run the same line again to update. Your data stays.

Heads up: http://localhost:8080 is the API server, not a website. Opening it in a browser shows nothing yet.

The web app lives in apps/web. For now you run it from the code with Node and Go: npm run dev there opens it at http://localhost:5173, talking to your server.

Set it up with your AI

Copy one prompt, paste it into Claude Code or Codex, and it installs Archive for you.

It checks Docker, asks for your email, runs the install, explains each step and helps you connect your AI.

API keys

Each space has one token. It opens that space, and nothing else.

Get it in the web app on the Connectors page, or from the command line:

docker exec archive archive token create -space finance

Send it with every request:

Authorization: Bearer <token>

Paste this into your AI

Get the token of my Archive space "finance" by running: docker exec archive archive token create -space finance. Save it as ARCHIVE_TOKEN in my .env file, add .env to .gitignore, and show me one test request to http://localhost:8080/api/types with it.
More detail
  • What it can do: edit in that one space. Read, add, change and delete its records and files.
  • Who sees it: the space's owners and admins can show it again any time.
  • Leaked? Rotate it. The old one stops working at once.
docker exec archive archive token rotate finance

Want one token for all your spaces? Make a personal one. It has your rights everywhere:

docker exec archive archive token create -name laptop -expires 720h

Terraform needs a full token, which can also manage spaces, members and tokens: archive token create -full.

MCP

Archive is an MCP server at /mcp, with one tool: run.

MCP is the standard way AI apps use outside tools. Add Archive once, with your token, and your AI can read and change your records.

Paste this into your AI

Connect this project to my Archive. It is an MCP server at http://localhost:8080/mcp using streamable HTTP, and it needs the header "Authorization: Bearer $ARCHIVE_TOKEN". Add it to your MCP config, then call its run tool with: return await archive.tables() and tell me which tables I have.

Claude Code

claude mcp add --transport http archive http://localhost:8080/mcp --header "Authorization: Bearer <token>"

Cursor

Add this to .cursor/mcp.json in your project:

{
  "mcpServers": {
    "archive": {
      "url": "http://localhost:8080/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}

Claude Desktop

On the machine that runs Archive, add this to claude_desktop_config.json. It talks to Archive directly, with no token, as the person you name:

{
  "mcpServers": {
    "archive": {
      "command": "docker",
      "args": ["exec", "-i", "archive", "archive", "-as", "you@example.com", "mcp"]
    }
  }
}

ChatGPT and claude.ai

These run in the cloud, so they need a public HTTPS address, not localhost. Archive also needs a bearer token, and it doesn't offer an OAuth sign-in yet. Use them only if their connector settings let you send that header.

Your own record types

Each kind of record is a real Postgres table. A row is one record.

CREATE TABLE invoice (
    id         uuid PRIMARY KEY DEFAULT uuidv7(),
    space      uuid NOT NULL REFERENCES archive.space,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    customer   text NOT NULL,
    amount     archive.money,
    search     tsvector GENERATED ALWAYS AS (archive.search_doc(customer)) STORED
);

You rarely write this yourself. Your AI does, see changing them.

More detail

What every table needs

The columns id, space, created_at, updated_at and search, a search index, and row-level security with policies. The rest of invoice.sql:

CREATE INDEX invoice_search ON invoice USING gin (search);
ALTER TABLE invoice ENABLE ROW LEVEL SECURITY;
ALTER TABLE invoice FORCE ROW LEVEL SECURITY;
CREATE POLICY viewer ON invoice FOR SELECT USING (space = ANY (archive.my_spaces()));
CREATE POLICY editor ON invoice USING (space = ANY (archive.my_spaces('editor')))
    WITH CHECK (space = ANY (archive.my_spaces('editor')));
COMMENT ON TABLE invoice IS 'icon: receipt';

Settings in comments

A table's comment holds only key: value lines. No descriptions. icon is a Lucide icon name. Views also take layout (table, board or calendar) and by, the column to group or place by.

CREATE VIEW task_board WITH (security_invoker = true) AS
    SELECT * FROM task WHERE status <> 'done';
COMMENT ON VIEW task_board IS 'layout: board
by: status
icon: kanban';

Built-in types

Ready-made column types that clean messy input: archive.email, phone, money, address, name, url, country, iban, vat_id, geo, quantity, timestamp and more. archive types lists them all.

So "€ 1.234,50" is stored as 1234.5 euros, and "06 12345678" as +31612345678.

Card numbers, US SSNs, Dutch BSNs, national ids and passports are secret types: stored encrypted, read back masked.

Change them with your AI

Ask for a new field or a new kind of record. Your AI shows you the plan, then applies it.

CustomerAmountDue Northwind€4,2001 Apr Acme€1,35015 Mar

Plan: ALTER TABLE invoice ADD COLUMN due date

Paste this into your AI

In my Archive, add a "due" date column to the invoice table. Use the run tool: get the files with archive.schema(), edit invoice.sql, and show me the plan from archive.apply(files). Only apply it with { confirm: true } after I say yes.

Or by hand: pull the schema as files, edit them, check the plan, apply.

archive schema pull ./schema
archive schema plan ./schema
archive schema apply ./schema
More detail
  • Plan and apply take the whole set. A table in no file gets dropped, so always pull first.
  • Dropping a table or column is blocked unless you pass -allow-drop. Dropping a view never is.
  • Renames aren't detected. Rename with ALTER TABLE ... RENAME first, or pass renames to archive.apply.
  • Only instance admins, or admins of a space, can change the schema.
  • Pulling and applying straight back plans nothing, so the files can live in git.

Search

One search covers every table and file you can see.

const hits = await archive.search("northwind", { type: "invoice" });

It matches the start of words and ignores case and accents: "nort" finds "Northwind", "cafe" finds "Café".

More detail

Filter by type, space, from and to dates. Up to 100 hits, 20 by default. File hits come with a snippet, matches in bold.

A table is found through the words in its search column, so put the columns people look for there.

archive search northwind -type invoice -from 2026-01-01

Files

Upload any file. Archive pulls out its text so search can find it.

curl -H "Authorization: Bearer $ARCHIVE_TOKEN" -F file=@contract.pdf "http://localhost:8080/api/files?space=finance"
More detail

Text comes out of PDF, HTML, plain text, JSON, email and pages. Images get thumbnails. All of it happens before the upload returns.

Plain uploads take up to 64 MB. Bigger files: resumable uploads at /api/files/tus.

Share a download with POST /api/files/{id}/link. It works for 24 hours without signing in. Add ?strip=gps to a photo download to drop its location.

Pages

Archive's own document. People and AI edit it together, live.

const notes = await archive.create("Meeting notes.page");
await archive.edit(notes.id, [{ op: "insert_paragraph_after", text: "Call the notary", style: "todo" }]);
More detail

A page is a list of blocks: paragraphs, headings, bullets, numbered items, to-dos, quotes and code. In the web app you see each other's cursors. AI edits show up live too.

Block ids never change, so an edit planned on an older read still lands right. No formatting, nesting or tables yet.

Office documents

Your AI can read and edit Word, Excel and PowerPoint files in place.

const budget = await archive.create("Budget.xlsx");
await archive.edit(budget.id, [{ op: "set_cell", cell: "B2", value: 1200 }]);
More detail

Edits only touch what they change. Everything else in the file stays byte for byte, so formatting, images and charts survive. If one edit fails, none are saved.

docxReplace text, insert or delete a paragraph, set a table cell.
xlsxSet a value or formula, clear a cell, add a row to an Excel table.
pptxReplace text, or all the text of a shape.

Not yet: new rows, columns or slides, formatting, and searching Office files by their text.

Code mode

Your AI writes one short script. Archive runs it inside, as you, and sends back one result.

Top: your AI calls Archive four times, one small step each. Bottom: one script, every step at once, one result back.

const unpaid = await archive.list("invoice", { where: { status: "unpaid" } });
const total = unpaid.reduce((sum, i) => sum + i.amount.amount, 0);
return { count: unpaid.length, total };
{"result": {"count": 3, "total": 6530}, "logs": [], "error": ""}
  • All or nothing. The script is one transaction. If it fails, nothing is saved.
  • As you. It only sees your spaces, even with raw SQL.
  • Time limit. 30 seconds by default. No network, no files.
  • Why it wins: one trip instead of dozens. Faster, cheaper, and no half-done changes.

Paste this into your AI

Use Archive's run tool. Write one TypeScript script that finds every invoice that is unpaid and older than 30 days, and returns the customer, amount and age of each. Return only what I need, not whole tables.
More detail

Archive strips the TypeScript types and runs the JavaScript inside the server. Scripts have archive, console and standard JavaScript. No fetch, imports or timers.

Limits: ARCHIVE_RUN_TIMEOUT (default 30s), 256 KB of result and 64 KB of logs.

Errors have a code: invalid, not_found, forbidden, conflict or a Postgres code. Invalid input lists every bad field. Catching an error undoes only that one call.

The run tool's description is the full SDK reference plus a type for each of your tables, so your AI writes against your real schema. See it yourself:

docker exec archive archive run -docs

Run scripts yourself with archive run script.ts or POST /api/run.

The SDK

Scripts call one object, archive, with one word per action.

Rows

listawait archive.list("invoice", { where: { status: "unpaid" }, limit: 20 })
getawait archive.get("invoice", id)
createawait archive.create("invoice", { customer: "Hart", amount: "€ 980" })
updateawait archive.update("invoice", id, { status: "paid" })
deleteawait archive.delete("invoice", id)
searchawait archive.search("northwind", { type: "invoice" })
sqlawait archive.sql("SELECT status, count(*) FROM invoice GROUP BY status")

Schema

tablesawait archive.tables()
schemaconst files = await archive.schema()
applyawait archive.apply(files, { confirm: true })

Files and documents

filesawait archive.files({ limit: 20 })
fileawait archive.file(id)
createawait archive.create("Budget.xlsx")
readawait archive.read(fileId)
editawait archive.edit(fileId, [{ op: "set_cell", cell: "B2", value: 1200 }])

Spaces

spacesawait archive.spaces()
More detail

update changes only what you pass; null clears a field. list goes oldest first; pass the last id as after for the next page.

New rows go to your own space unless you pass { space: "finance" }.

Secret fields read back masked. Pass { reveal: true } to list or get to see them, if you're allowed.

Spaces


A space is a shared box of records and files. People only see the spaces they're in.


docker exec archive archive space add finance


Everyone also gets a private space of their own. New records go there unless you pick another.







People and roles


Add someone, give them a role in a space, and they can sign in.


docker exec archive archive user add anna@example.com -name Anna
docker exec archive archive space grant finance anna@example.com editor




viewerReads.


editorAlso adds, changes and deletes.


adminAlso manages members, the space token and the schema.


ownerEverything, including deleting the space.




Signing in


No passwords. Sign-in links work once, for 15 minutes. Without a mail server they're printed in the log: run docker logs archive and look for sign-in link for.


Archive sends no invitations. An instance admin adds the person, then a space admin gives them a role. Grant none to remove someone.


Passkeys work through the sign-in API at /auth/passkey. The web app has no passkey button yet.


Google or Microsoft sign-in: list them in ARCHIVE_OIDC, with ARCHIVE_URL/auth/oidc/<name>/callback as the redirect address. Only people who already have an account get in.


ARCHIVE_OIDC='[{"name": "google", "issuer": "https://accounts.google.com", "client_id": "...", "client_secret": "..."}]'









Privacy and security


The database itself checks every row against who's asking.


    

  • Row-level security: each table has a rule, "only rows from your spaces". It applies to the app, the API, your AI and raw SQL alike.
    • 

  • Tokens only narrow: a token can never do more than its owner.
    • 

  • Secret fields: encrypted, masked, and only shown to people an admin allows.
    • 

  • Sandboxed scripts: no network, no files, a time limit.
    • 



docker exec archive archive secret grant anna@example.com passport







Install


The install line runs one Docker container, with all data in one volume.


curl -fsSL https://raw.githubusercontent.com/Mulholland-Inc/archive/main/install.sh | ARCHIVE_ADMIN_EMAIL=you@example.com ARCHIVE_PORT=9090 sh


Put settings in front of sh, like the port above.


More detail


It checks Docker, pulls ghcr.io/mulholland-inc/archive:latest, and runs a container named archive on port 8080. Data goes in a Docker volume, also named archive.


From the code, compose.yaml does the same:


ARCHIVE_ADMIN_EMAIL=you@example.com docker compose up -d









Settings


Everything is an environment variable. On your own machine you may need none.




ARCHIVE_URLPublic address for links, cookies and passkeys.


ARCHIVE_ADMIN_EMAILThe first owner, made when there are no users yet.


ARCHIVE_SMTP_URLMail server for sign-in links, like smtp://user:pass@host:587.


ARCHIVE_LOCALEHow to read messy input, like nl-NL.




All settings




ARCHIVE_DATAData folder. /data in Docker.


ARCHIVE_SMTP_FROMSender address.


ARCHIVE_OIDCGoogle, Microsoft or other sign-in, as JSON.


DATABASE_URLAn outside Postgres, as a superuser.


ARCHIVE_SECRET_KEY32-byte key for secret fields. Needed with DATABASE_URL.


ARCHIVE_BLOB_URLS3-compatible storage for files.


ARCHIVE_BLOB_KEY, ARCHIVE_BLOB_SECRETIts access key and secret.


ARCHIVE_INSTANCEPrefix for database roles. Default a.


ARCHIVE_PG_BINWhere to find Postgres programs.


ARCHIVE_RUN_TIMEOUTTime limit per script. Default 30s.


ANTHROPIC_API_KEYTurns on the chat in the web app.


ARCHIVE_MODELIts model. Default claude-haiku-5-5.

The install script doesn't pass ARCHIVE_RUN_TIMEOUT, ANTHROPIC_API_KEY or ARCHIVE_MODEL into the container. Add those with docker run -e or in compose.yaml.









Production


Put it behind HTTPS and set ARCHIVE_URL. That's most of it.


archive.example.com {
    reverse_proxy localhost:8080
}


That's a Caddy config: a small web server in front that handles certificates.


More detail


Many servers, nothing local


Give Archive an outside Postgres, S3-compatible storage and one secret key. Then any number of copies can run side by side.


DATABASE_URL=postgres://archive:...@db.example.com:5432/archive
ARCHIVE_BLOB_URL=s3://archive-files/prod?endpoint=https://s3.eu-west-1.amazonaws.com&region=eu-west-1
ARCHIVE_SECRET_KEY=$(openssl rand -hex 32)


Use the same key everywhere. Archive won't start with DATABASE_URL and no key. Managed Postgres without a true superuser, like Cloud SQL, and GCS through its S3 interface are not tested yet.


Kubernetes and Terraform


helm install archive apps/helm/archive --set url=https://archive.example.com --set adminEmail=you@example.com


apps/terraform has ready setups for AWS (Fargate, RDS, S3), Google Cloud (Cloud Run, Cloud SQL, Cloud Storage) and Azure (Container Apps, Postgres, Azure Files). There is also an archive Terraform provider for your schema, tokens and roles.









Upgrades and backups


Run the install line again to upgrade. Archive backs itself up first.


With the built-in database, a backup lands in /data/backups before each new version. The last three are kept.


With an outside database, back up the database and the file storage. Keep your secret key safe: without it, secret fields can't be read.
