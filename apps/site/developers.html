curl "https://your-workspace.archive.mulholland.ai/api/invoice?space=acme" \
  -H "Authorization: Bearer $ARCHIVE_TOKEN" \
  -d '{"customer": "Northwind", "total": {"amount": 1240, "currency": "USD"}, "due": "2026-11-30"}'

curl "https://your-workspace.archive.mulholland.ai/api/invoice?customer=Northwind&limit=20" \
  -H "Authorization: Bearer $ARCHIVE_TOKEN"
await archive.create("invoice", {
  customer: "Northwind",
  total: { amount: 1240, currency: "USD" },
  due: "2026-11-30",
}, { space: "acme" })

return archive.list("invoice", { where: { customer: "Northwind" }, limit: 20 })
archive create invoice -space acme \
  '{"customer": "Northwind", "total": {"amount": 1240, "currency": "USD"}, "due": "2026-11-30"}'

archive list invoice -limit 20 customer=Northwind

archive search "Northwind" -type invoice -from 2026-10-01

The API, route by route.

Every request carries a sign-in or an access key. When something is wrong, you get a clear reason and a note on each field to fix.

EndpointWhat it does
GET /api/typesEvery table and view with its columns, comments and references.
GET /api/{type}List rows, oldest first. Filter with column=value, page with limit and after, add reveal=true for granted secrets.
POST /api/{type}Create a row, cleaned and validated per field, in your space or ?space=.
GET /api/{type}/{id}One row.
PATCH /api/{type}/{id}Change some fields; null clears one.
PUT /api/{type}/{id}Replace the whole row.
DELETE /api/{type}/{id}Delete a row.
GET /api/searchFull-text search over rows and files with q, type, space, from, to and limit.
GET|POST /api/filesList files, or upload one as multipart form data. Large files use resumable tus uploads at /api/files/tus.
GET /api/files/{id}/contentThe file's bytes. /text gives its extracted text, /thumbnail an image preview.
POST /api/files/{id}/linkA short-lived signed download link.
GET /api/schemaDDL generated from the database, one <name>.sql per table or view.
POST /api/schema/planPlan the whole set of files against the database, with hazards per statement.
POST /api/schema/applyApply that plan. Takes renames and allow_drop.
POST /api/runRun TypeScript against the SDK in one transaction; returns result, logs and error.
GET /api/run/docsThe SDK docs, with an interface per table.
GET /api/pages/{id}/syncA server-sent event stream: the page, then everyone's operations and presence.
POST /api/pages/{id}/opsSend a tab's go-crdt operations; /presence sends a caret, a name and a colour.
/auth/spaces, /auth/tokensSpaces, members and scoped tokens.

Every script command.

Each one is fully typed, so your editor helps as you write. Errors tell you plainly whether something was invalid, missing, not allowed or in conflict.

VerbWhat it does
sql(query, ...params)Run one SQL statement as you, with $1, $2 bound to params.
list(table, opts)Rows of a table, oldest first, filtered by where and paged with after.
get(table, id)One row by id.
create(table, data)Insert a cleaned, validated row. create("Notes.page") makes an empty page, docx, xlsx or pptx.
update(table, id, patch)Change the given fields; null clears one.
delete(table, id)Delete a row.
search(text, opts)Full-text search over every table and file you can see, best first.
schema()DDL generated from the database, one file per table or view.
apply(files, opts)Plan the whole set of DDL files; with confirm, apply it.
tables()Every table and view with its columns, types, comments and references.
files(opts)Files you can see, oldest first, with their extracted text.
file(id)One file with its extracted text.
read(fileId)The structure of a docx, xlsx, pptx or page: paragraphs, cells, slides and shapes.
edit(fileId, edits)Apply a list of edits to a document, all or nothing.
spaces()The spaces you can see, with your role in each.

The archive command line.

Every command acts as a real person with their permissions. Its output is easy for scripts, scheduled jobs and CI to read.

CommandWhat it does
archive run <file.ts|->Run TypeScript against the SDK in one transaction. -docs prints the SDK docs.
archive typesPrint the tables, their columns and the built-in types.
archive schema pull [dir]Print the generated DDL, or write one <name>.sql per table or view into dir.
archive schema plan <dir>Show the statements that bring the database to the files in dir.
archive schema apply <dir>Run that plan. -allow-drop lets statements that delete data through.
archive list <table>List rows with column=value filters, -limit, -after and -reveal.
archive get <table> <id>One row.
archive create <table> [json]Create a row from the argument or stdin, in -space or your own.
archive set | updateSet some columns, or replace the whole row.
archive delete <table> <id>Delete a row.
archive search <query>Find rows and files by their words, with -type, -space, -from and -to.
archive file add|get|listStore files and extract their text, print their metadata, or write their content.
archive space add|list|members|grant|removeMake spaces and set who holds which role in them.
archive token create|list|revokeScoped tokens with a role per space and an expiry.
archive secret grant|revokeLet a person read one secret type, like us_ssn or passport.

Your workspace, as code.

Keep the shape of your data, your access keys and who can do what in Terraform, next to the rest of your stack. Archive previews each change itself, so you never chase false differences.

  • A

    Your structure

    Every kind of record and every board, previewed and applied together.

  • B

    Who can do what

    What each person can see and change in a space.

  • C

    Access keys

    A key for an AI assistant or a service, limited in scope and time.

  • D

    Your spaces

    A list of every space a key can reach.

terraform {
  required_providers {
    archive = { source = "mulholland-inc/archive" }
  }
}

provider "archive" {
  endpoint = "https://your-workspace.archive.mulholland.ai"
}

resource "archive_schema" "main" {
  files = {
    for f in fileset("${path.module}/schema", "*.sql") :
    f => file("${path.module}/schema/${f}")
  }
}

resource "archive_policy" "sam" {
  space = "acme"
  user  = "sam@acme.com"
  role  = "editor"
}

resource "archive_token" "intake" {
  name    = "intake-agent"
  spaces  = { acme = "editor" }
  expires = "720h"
}
CREATE TABLE house (
    id         uuid PRIMARY KEY DEFAULT uuidv7(),
    space      uuid NOT NULL REFERENCES archive.space,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    address    text NOT NULL,
    price      archive.money,
    search     tsvector GENERATED ALWAYS AS (archive.search_doc(address)) STORED
);
CREATE INDEX house_search ON house USING gin (search);
ALTER TABLE house ENABLE ROW LEVEL SECURITY;
ALTER TABLE house FORCE ROW LEVEL SECURITY;
CREATE POLICY viewer ON house FOR SELECT USING (space = ANY (archive.my_spaces()));
CREATE POLICY editor ON house USING (space = ANY (archive.my_spaces('editor')))
    WITH CHECK (space = ANY (archive.my_spaces('editor')));
COMMENT ON TABLE house IS 'A house you own or rent

Under the hood.

Pages that update live, changes that never end up half done, and servers that rest when nobody is working.

Live pages

  • Everyone's edits appear on screen as they happen
  • Edits from people and AI merge on their own, so nothing gets lost
  • See who is on the page and where they are typing

All or nothing

  • If a script fails or runs out of time, nothing is saved
  • An error you handle undoes only that one step
  • Live updates and file processing wait until the work is saved

Rests when idle

  • No single server holds anything, so any one can answer
  • Nothing runs between requests
  • An open page keeps things awake only while it is open

Developer questions.

The rest is in the docs.

Which AI assistants can connect?

Any assistant that supports remote connectors with an access key, including ChatGPT, Claude, Gemini, Grok, Claude Code and Cursor. Give it your workspace link and a key.

What can a script do, and for how long?

It can use Archive and standard JavaScript, but it cannot reach the internet, import code, set timers or open files. Each run has a time limit, up to 256 KB of results and 64 KB of logs.

How do I give an AI assistant its own access?

Make an access key from the command line, the API or Terraform, and choose what it can do in each space and when it expires. It can never do more than you can.

Can I keep my structure in git?

Yes. Pull it as one file for each kind of record or board, edit, preview and apply. Applying what you just pulled changes nothing, so the files stay stable.

How do I page through a lot of records?

Lists come back oldest first. Pass the last id you saw as after to get the next page.
